# Работа с длинным контекстом

Используй эти рекомендации при заметной потере решений, повторном чтении
уже проверенных источников или подготовке передачи работы. Число сообщений
и вызовов инструментов само по себе не измеряет оставшийся контекст.

- Читай нужные части источников: сначала поиск по именам/заголовкам, затем
  выбранный фрагмент. Сохраняй достаточно контекста для проверки смысла.
- Используй уже существующий канон проекта и актуальные решения пользователя.
  Навыки `project-memory` и `structured-artifacts` помогают организовать
  разрешённые записи; длинная задача сама по себе не разрешает создание памяти.
- Сохраняй короткие проверяемые промежуточные результаты, ссылки на исходники,
  принятые решения и открытые вопросы в разрешённых рабочих артефактах.
- Делегируй ограниченные независимые подзадачи по необходимости и возможностям
  host. Передавай существенные источники и решения, а не весь массив по умолчанию.
- Используй доступный режим длительных команд так, чтобы сохранять возможность
  получить новое указание пользователя и сообщить существенный результат.

При сжатии контекста продолжай ту же задачу: прежние решения и выполненная
работа сохраняют силу. Не объявляй их утраченными только из-за compaction.
Если восстановить критичную вводную из доступных источников нельзя, назови
конкретный пробел и уточни его, продолжая независимую работу.

Передача в другую задачу уместна по просьбе пользователя или после согласования,
если реально поможет сохранить точность. Подготовь передачу по существующему
`handoff-to-new-chat`, соблюдая его актуальную область применения и разрешения.
Автоматические пороги процентов и числа turns не являются основанием
прерывать работу или создавать новую задачу.
