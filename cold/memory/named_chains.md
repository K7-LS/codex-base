# Named chains — `~/.codex/base/cold/chains/`

Загружать по триггерам: «составь pipeline», «многошаговая задача», «собери комплект
документов», «весь процесс от ТЗ до сдачи». Методология создания — скилл `chains-pattern`.
Определения доступных цепочек — Markdown-файлы в `~/.codex/base/cold/chains/`.

Для типовых многошаговых сценариев (3+ stage с зависимостями) — именованные цепочки
в `~/.codex/base/cold/chains/`. Для короткой задачи отдельная цепочка не нужна.

| Chain | Когда срабатывает | Status |
|-------|-------------------|--------|
| `chain:docx-from-template` | «сгенерируй документ по шаблону», «заполни шаблон» | ✅ |
| `chain:pdf-scan-extract` | «разбери скан-PDF», «извлеки данные из скана» | ✅ |
| `chain:project-doc-pack` | «собери комплект ПЗ + спецификация + ведомости» | 🚧 stub (зависит от stage-decomposition `designer`) |
| `chain:design-stamp-corrections` | «правки по замечаниям», «исправить замечания», «обновить спецификацию по экспертизе», «синхронизировать штамп» | Не поставляется; отдельного определения нет |
| `chain:upd-to-spec-reconcile` | «пришёл УПД, обнови реестр», «применить УПД к Спец», «обнови S по УПД», «сверь УПД с реестром» | ✅ |

**Логика оркестратора:**
1. При совпадении задачи проверить наличие определения и его статус `active`.
   Прочитать соответствующий файл из указанного каталога и выполнить применимые шаги.
   Отметка stub или отсутствие файла не являются работающей цепочкой: выбрать
   доступный предметный workflow, явно назвав предел, если обязательный процесс недоступен.
2. Если не совпадает — стандартный flow main → доменный агент → ревьюер.
3. **На каждом шаге chain — обязателен verify-критерий** (Karpathy §4).
4. При провале verify устранить подтверждённую причину в разрешённых пределах и
   перепроверить результат. Зависимый шаг не продолжать без выполненного критерия;
   существенный блокер сообщить пользователю, независимую работу сохранить.
