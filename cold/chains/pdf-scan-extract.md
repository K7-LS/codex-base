# chain:pdf-scan-extract

## Назначение

Извлечение данных из сканированного PDF: определение типа
(скан vs текстовый), OCR с координатами, структурирование в JSON,
опциональная валидация значений.

## Шаги

### Stage 1 — detect (collect)

Через `doc-extract` проверить текстовый слой и изображения на нужных страницах
доступным средством чтения PDF. Почти пустой текст при наличии изображения —
основание проверить страницу как скан и перейти к OCR. Смешанный PDF оценивать
постранично; текстовые страницы извлекать без OCR по методике `doc-extract`.

**Verify:** явный признак scan vs text (text length, image count)
задокументирован в выводе.

### Stage 2 — OCR (extract)

Выполнить OCR через доступное средство извлечения по `doc-extract` с языками
документа. Для таблиц и поиска соседних полей нужны координаты и номера страниц.
Не запускать pipeline замены текста в изображении ради чтения скана; отдельную
OCR-операцию использовать только после проверки её реального интерфейса.

**Verify:** OCR вернул не пустой список токенов. Если пустой —
проверить страницу визуально и допустимый способ извлечения. Если нужные данные
не восстановлены — сообщить точный предел и запросить недостающий исходник.

### Stage 3 — structure (extract → JSON)

По задаче пользователя — выделить ключевые значения:

- если это таблица счёта:
  `{counterparty, inn, sum, vat, items, date}`;
- если это форма: `{field_name: value}` для каждой подтверждённой по странице
  пары label→value; неоднозначное соседство само не доказывает связь;
- иначе — список токенов с координатами как есть.

**Verify:** JSON соответствует ожидаемой схеме (поля непустые,
типы правильные, ИНН 10 или 12 цифр, суммы > 0 если применимо).

### Stage 4 — return / validate

Вернуть JSON пользователю. Если задача требует валидации (сумма > 0,
ИНН валиден, дата в разумном диапазоне) — прогнать проверки и
подсветить расхождения.

**Verify:** все обязательные поля валидны, расхождения явно указаны.

## Когда НЕ использовать

- Текстовый PDF с text layer — skill doc-extract справится
  без OCR (pymupdf).
- Растровое изображение (PNG/JPG) без PDF-обёртки → доступный OCR по `doc-extract`.
- При низком качестве проверить читаемость нужных данных; новый скан просить,
  если восстановить существенные сведения имеющимися средствами не удалось.
