# Hindsight: выборочная память проекта

Используй этот маршрут только по прямому запросу владельца на Hindsight.
Hindsight хранит извлечённый опыт и даёт подсказки агентам; принятые факты,
решения, статус и ссылки на доказательства остаются в существующем каноне
проекта. Ответ памяти не доказывает актуальность исходника: перед существенным
выводом сверяй его с проектными файлами.

## Граница данных

- Настройки подключения хранятся в профиле пользователя
  `~/.hindsight/coding-agent.json`, а не в release Codex Base или репозитории
  проекта. Не помещай туда токены, которые попадут в Git или отчёт.
- Сначала `optInOnly: true`; допускай только явно выбранные корни проектов.
  Для Codex и Claude одного проекта укажи одинаковый банк через
  `mapPathToBank` на каждом устройстве. Не назначай один банк всем проектам.
- Для первоначального включения используй `gitIngest: "none"`,
  `autoSeed: false`, `codebaseSurvey: false`, `autoInject: "recall"`,
  `recallOptions.types: ["world", "experience", "observation"]` и
  `autoUpdate: false`; не запускай `--import-conversations`. По умолчанию
  `autoSeed` и `codebaseSurvey` могут вызвать отдельное чтение репозитория
  моделью, а `autoInject: "reflect"` — модельный синтез подсказки. При
  отключённой консолидации банка поиск только observations может вернуть пусто;
  перечисленные `recallOptions.types` сохраняют поиск исходных фактов.
  Полные новые сессии могут отправляться на выбранный сервер при
  `retainSessions: true`; прежде чем включить, проверь согласованную границу
  проекта и доступ к серверу. Извлечение фактов из новых сеансов также
  расходует лимит выбранной для Hindsight модели.
- Не копируй на сервер локальный `auth.json`, профили Claude, архивы сессий
  или историю браузера. Авторизацию подписки для сервера выполняют в отдельном
  каталоге учётных данных через штатный интерактивный вход провайдера.

## Подключение

Текущий пакет — `@vectorize-io/hindsight-coding-agents`, отдельные старые
интеграции Codex и Claude заменены им. Выбери конкретную проверенную версию
пакета и явно укажи режим `self-hosted` с адресом своего локального API;
не используй `install all`. Локальный API слушает только `127.0.0.1`.
Установщик
для Codex добавляет три хука в `~/.codex/hooks.json` и MCP в
`~/.codex/config.toml`; для Claude — хуки в настройках Claude Code.

`$sync-base` заменяет `~/.codex/hooks.json`. Перенос трёх хуков Hindsight в
`[hooks]` того же пользовательского `config.toml` тоже неверен: Codex читает
оба файла, запускает оба набора и показывает предупреждение. Для выбранного
доверенного проекта используй отдельный слой `<project>/.codex/hooks.json`.
Шаблон в `assets/hindsight-project-hooks/` этого навыка вызывает локальный
Hindsight только при наличии установленного пакета и его настройки; копируй
его в проект лишь после проверки существующих проектных хуков, не перетирая их.
Сохрани резервные копии `~/.codex/config.toml` и `~/.codex/hooks.json`, затем
убери только старые три Hindsight-хука из пользовательского слоя. Утилита
`~/.codex/base/runtime/maintenance/repair_codex_config.py` может сделать это
после диагностики с аргументами `--home <home> --project <project> --apply`;
она не удаляет смешанные или неизвестные хуки. Проверь `/hooks` и дай доверие
проектным хукам, затем запусти `sync-base plan` и `doctor`. После обновления
пакета Hindsight проверь, не вернул ли установщик глобальные хуки.

Установщик также кладёт навык Hindsight в `~/.agents/skills`, где Foundation
Codex считает его неизвестным и строгий `doctor` не проходит. После проверки
точного пути и резервной копии перенеси только этот навык в
`~/.codex/skills/hindsight-coding-agent` — пользовательский каталог навыков
Codex за пределами инвентаря Foundation. Повтори этот шаг после ручного
обновления coding-agents, если установщик снова создаст каталог в
`~/.agents/skills`. Не обходи `doctor` правкой `active.json`.

Локальный `hindsight-api` может работать со встроенным PostgreSQL (`pg0`).
Не выставляй API или PostgreSQL в сеть; на другом ПК память поднимают из
резервной копии. `hindsight-admin backup` сохраняет полный снимок, а
`restore` заменяет данные целевой базы: сначала инициализируй отдельную
тестовую базу, после восстановления выполни
`hindsight-admin repair-bank --all` для частичных векторных индексов и проверь
поиск записи. Не синхронизируй живую
папку `pg0` как файловую базу. Архив содержит разговоры и факты; место его
внешнего хранения и защиту согласуй отдельно. Не помещай auth и архивы в
release базы.

## Приёмка

1. Неразрешённый проект не создаёт банк и не отправляет сессию.
2. Codex и Claude в выбранном проекте видят одну запись в общем банке;
   другой проект её не видит. Канон проекта не переписывается автоматически.
   Если в банке ещё нет knowledge pages, первый запрос нового сеанса может
   пройти без подсказки; проверь и второй запрос того же сеанса.
3. `sync-base` сохраняет три Hindsight-хука, MCP и собственный SessionStart
   базы без дублей; после обновления это подтверждено живым запуском.
4. Локальный API доступен только через `127.0.0.1`; запись, поиск и
   восстановление из резервной копии проходят. Если сервер выносят в сеть,
   перед подключением нужны HTTPS и Bearer-аутентификация.

Если пункт не проверен, укажи `NOT_RUN` или `BLOCKED` именно для него,
не объявляй развёртывание завершённым.
