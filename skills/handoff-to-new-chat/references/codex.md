# Передача работы в Codex

Используй после подготовки пакета по `../SKILL.md`, когда требуется выбрать
конкретную операцию текущего клиента. Доступные инструменты и их действующая
схема определяют механизм; этот файл не фиксирует модель, тариф или лимит окна.

## Выбор операции

- **Продолжение той же задачи.** Сохрани действующие решения и продолжай работу,
  в том числе после compaction. Не создавай другую задачу для обычного продолжения.
- **Новый промпт или отчёт.** Подготовь запрошенный материал. Сам по себе этот
  запрос не разрешает создание задачи или отправку пакета другому участнику.
- **Явная просьба создать новую задачу.** Найди предназначенный для этого
  доступный инструмент, прочитай схему и выбери разрешённую рабочую среду.
  Не назначай модель и уровень рассуждений без указания пользователя.
- **Разветвление или перенос существующей задачи.** Выполняй запрошенную операцию
  через доступный механизм host. Проверь, что переносится: файлы, изменения,
  завершённая история, активные процессы. Не считай ветвление сокращением контекста.

Не подставляй команды или UI-жесты из старой версии клиента. Если механизм
неясен, проверь доступные локальные инструменты и справку; при необходимости
обратись к актуальной официальной документации. Когда нужная операция недоступна,
выдай готовый пакет и назови конкретный оставшийся ручной шаг.

## Контекст и результат передачи

Если host предоставляет измерение контекста, укажи его фактическое значение
с источником, когда это нужно для решения. Не оценивай лимит по числу turns,
названию подписки или догадке о модели. Показатель сам по себе не разрешает
остановить работу или создать другую задачу.

После разрешённой операции проверь её статус. Принятое в очередь создание,
готовая задача и реально начатое продолжение — разные состояния. Передай
пользователю подтверждённый результат и существенные ограничения.

Пакет содержит рабочую цель, источники, текущие решения, разрешения и следующий
шаг. Внутренние auth, session и state-файлы клиента не копируй и не редактируй.
