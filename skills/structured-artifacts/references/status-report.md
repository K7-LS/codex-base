# Статический отчёт по состоянию задачи

Применяй для длительной задачи, если пользователю полезно видеть требования,
открытые вопросы и замечания в одном HTML-файле. Короткая задача не требует
проекции или отчёта. Источником решений остаются существующие канонические
файлы проекта; JSON и HTML служат их явно подготовленным представлением.

## Подготовка и запуск

1. Прочитай актуальные источники и основания состояний. Подготовь небольшую
   JSON-проекцию в UTF-8. Укажи время, к которому относятся данные, и SHA256
   точных байтов каждого упомянутого файла.
2. Используй обычный каталог проекта без symlink, junction и других reparse
   points в пути. Проекция, источники и выходной HTML должны находиться внутри
   него. Каталог для HTML создай заранее.
3. Выполни явную команду с Python 3.11 или новее; внешние библиотеки не нужны:

```powershell
$tool = Join-Path $env:USERPROFILE ".agents\skills\structured-artifacts\tools\render-status.py"
python -X utf8 $tool `
  --root "C:\Работа\Объект" `
  --input "отчёты\status.json" `
  --output "отчёты\status.html"
```

Путь к скрипту в примере соответствует установленному навыку Windows.
При другом расположении используй фактический каталог навыка. `python` здесь
означает уже доступный Python 3.11+: при необходимости укажи его полный путь.
Пути `--input` и `--output` разрешаются относительно `--root`. Допустимы и
абсолютные пути внутри этого корня. Запуск не открывает браузер, не поднимает
сервер и не создаёт фоновую задачу. Полученный файл можно открыть вручную.

## Контракт проекции

Все шесть полей верхнего уровня обязательны. Неизвестные и повторяющиеся
JSON-ключи отклоняются. Максимальный размер проекции — 1 MiB; каждый список
содержит до 1000 элементов, отдельная строка — до 10 000 символов.

| Поле | Значение |
|---|---|
| `title` | Непустое название отчёта |
| `as_of` | ISO 8601 с часовым поясом: например, `2026-09-10T12:00:00+03:00` |
| `canonical_sources` | Непустой список ссылок на действующий канон задачи |
| `requirements` | Список требований; может быть пустым |
| `open_questions` | Список текстов открытых вопросов; может быть пустым |
| `findings` | Список текстов замечаний; может быть пустым |

Требование содержит обязательные `id`, `text`, `state`. Идентификаторы должны
быть уникальными. Необязательные поля: `result` — текст результата, `sources`
— список оснований требования, `evidence` — список доказательств результата.

| `state` | Подпись в отчёте |
|---|---|
| `pending` | Не начато |
| `in_progress` | В работе |
| `awaiting_decision` | Ожидает решения |
| `needs_review` | Требует проверки |
| `accepted` | Принято по данным источника |
| `failed` | Ошибка |
| `skipped` | Пропущено |

Любая ссылка в `canonical_sources`, `sources` или `evidence` имеет поля
`path` и `sha256`, а при необходимости — `locator`. Путь относителен от
`--root`; допустимы `/` и `\`, пробелы и кириллица. SHA256 — 64 шестнадцатеричных
символа. `locator` уточняет страницу, строку или элемент для человека;
скрипт не проверяет наличие этого элемента внутри документа.

```json
{"path": "Канон/STATUS.md", "sha256": "<SHA256 точных байтов файла>", "locator": "R-03"}
```

Это иллюстрация ссылки: строку в угловых скобках необходимо заменить настоящим
хешем. Готовая синтетическая проекция находится в
`status-report.example.json`; она ссылается на этот справочник и не описывает
состояние реального проекта. При изменении справочника пример потребует
осмысленного обновления ссылки и хеша.

## Проверка и границы результата

`accepted` допустим только с непустым `result` и хотя бы одной ссылкой
`evidence`, когда хеши всех файлов совпали. Это проверка полноты представления:
содержание, достаточность доказательств и инженерное принятие остаются за
профильной проверкой и действующим маршрутом согласования. Название файла,
его наличие и совпадение SHA256 сами по себе не доказывают качество работы.

Скрипт показывает исходные состояния и их количества. Он не вычисляет процент
готовности, не принимает результат по времени или числу шагов и не превращает
`skipped` в `accepted`. Пустые вопросы означают лишь, что они не указаны в
проекции.

Перед записью проверяются JSON, границы путей, наличие файлов и хеши; перед
атомарной заменой HTML хеши проверяются повторно. Повреждённые данные,
изменившийся источник, недоступный путь или попытка перезаписать проекцию либо
исходный файл завершают команду с кодом 2. Существующий HTML сохраняется;
сообщение об ошибке прямо запрещает считать прежний файл актуальным.
Успешное формирование возвращает код 0. Не обновляй хеши автоматически,
чтобы скрыть расхождение: сначала проверь изменившееся содержание.

В HTML видны `as_of`, время формирования и SHA256 проекции. Это снимок:
последующие изменения файлов он не отслеживает. Скрипт не определяет свежесть
решения по смыслу или возрасту и не проверяет достоверность введённого времени.
Файлы с совпавшими хешами могут содержать устаревшее решение. Ссылки локальны
и работают, пока сохранено относительное расположение отчёта и источников;
перед передачей HTML проверь допустимость выдачи его текста и имён файлов.

Текст экранируется, пути в ссылках кодируются. Отчёт не содержит JavaScript,
удалённых ресурсов, сетевых запросов или средств управления процессами.
Защита путей рассчитана на обычную локальную работу; одновременная враждебная
подмена файловой системы отдельным процессом не является защищённым режимом.
