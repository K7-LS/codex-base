# domain-grilling

Use for substantive construction and engineering work when a missing input can
change quantities, equipment, compliance, cost, or the delivered document.
Examples: design calculations, equipment selection, specifications, bills of
quantities, estimates, execution documents and expert-review responses.

## Native Codex flow

1. Read available project files, accepted decisions and relevant authoritative
   sources. Identify what is known and which missing inputs materially affect
   the result. Never ask for a fact already present in the supplied source.
2. Ask when a remaining choice changes the result, cost, deadline, design or
   responsibility. Explain the consequences and recommend an option when the
   evidence supports it. Group related independent questions when useful;
   resolve dependent questions after the preceding answer.
3. Use an available host question tool, including an asynchronous one, or a
   concise ordinary question. Follow its actual contract. Keep dependent work
   pending until the necessary answer arrives and continue independent work.
   Silence, a timeout and a preselected option are not an answer or consent.
4. Revisit questions when new evidence creates a material branch during the
   task. Choose equivalent reversible implementation steps independently;
   do not reconfirm an accepted decision without a new reason.
5. Keep accepted decisions in the working context; persist them in the existing
   project canon only when its rules or the user authorize that write. Use a
   plan for complex or risky work, not merely because questions can be counted.
6. Proceed when the decisions needed for the next action are resolved. Do not
   turn clarification into a separate interview that delays ready work.

Use `norm-lookup` for an exact normative claim. Do not quote a standard from
memory. If a required input remains unavailable, name it and mark the dependent
part `BLOCKED`; identify what can still be completed without inventing data.

## Opt-out and small tasks

With complete inputs or an unambiguous narrow request, perform the task without
an interview. `Без грилинга` / `вводные полные` asks for less questioning; it does
not authorize invented quantities or a silent choice with material consequences.
Read the supplied inputs first and raise only a remaining decisive gap.

This skill does not install or configure hooks, plugins or tools. Follow the
base permission rules for any such change. Discovery and activation must be
verified in the target host; the presence of this file alone proves neither.
