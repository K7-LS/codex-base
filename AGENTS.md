# Codex Base

Отвечай пользователю на языке запроса. Код, пути и идентификаторы сохраняй в
их исходной форме.

## Рабочий режим

- Простой разговор и короткое объяснение выполняй инлайн без инструментов,
  custom agents и ревьюеров.
- Перед существенным изменением изучи реальные файлы и выбери минимальный
  проверяемый шаг. Повторяемую точную обработку делай кодом.
- Для крупной или рискованной реализации используй нативный Plan Mode.
  Не запускай отдельный brainstorming workflow.
- Загружай полный навык только после совпадения задачи с его кратким
  описанием. References, scripts и templates читай по необходимости.
- Custom agent вызывай только для подходящего домена, когда это разрешает
  политика текущего host. Не создавай fan-out по умолчанию.

## Маршрутизация и проверка

- Расчёты инженерных систем и подбор оборудования → `designer`.
- Объёмы, ВОР, спецификации и пояснительные записки → `pto-engineer`.
- Стоимость, расценки и КС-2/КС-3 → `сметчик`.
- Закупки, УПД и входящие предложения → `снабженец`.
- Исполнительная документация → `id-engineer`.
- Точная нормативная цитата → `norm-lookup`; не цитируй нормы по памяти.
- Проверка одного раздела по нормам → `audit-rd-section`.
- Согласованность нескольких разделов → `rd-coordinator`.

Reviewer-гейт обязателен для выдаваемых документов, количеств, нормативных
ссылок и дорогих или необратимых решений. Форму файла проверяет профильный
reviewer, содержание по источникам — `auditor`. Для обычного ответа или
диагностики reviewer не нужен. Недоступное для проверки не считается PASS.

## Инструменты и безопасность

- Инструменты подключаются лениво по `required_capabilities` выбранного навыка.
- Не устанавливай и не включай MCP, plugins, логины или внешние программы без
  разрешения. Недоступная обязательная capability → `BLOCKED` с её именем и
  безопасным следующим шагом.
- Не фиксируй модель или reasoning-level в файлах базы.
- Не изменяй auth, sessions, memories, state и внешние рабочие папки.
- Соблюдай локальные проектные инструкции; они уточняют эту глобальную базу,
  но не отменяют её запреты и permission gates.

## Обновление базы

Поток обновлений только hub → consumer. `$sync-base` проверяет подписанный
стабильный release, строит plan, создаёт backup, устанавливает пакет, запускает
doctor и при ошибке делает rollback. Текст `/sync-base` — алиас того же навыка.

Consumer никогда не отправляет feedback, телеметрию, отчёты сессий, credentials
или локальные изменения. SessionStart только проверяет наличие новой версии с
TTL и молчит, если обновления нет.
